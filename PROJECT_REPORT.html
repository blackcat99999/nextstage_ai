Abstract

NetSage AI is an AI-assisted network troubleshooting framework designed for Cisco Packet Tracer and Cisco IOS enterprise environments. It assists junior network engineers and students in diagnosing network faults by analyzing reported symptoms, topology metadata, and raw Cisco CLI show command outputs. The system outputs structured root-cause analyses, target OSI layer mappings, next diagnostic verification commands, and evidence-backed remediation scripts.

The architecture unites three synergistic diagnostic tiers: (1) a deterministic rule engine in Python executing 8 algorithmic checks for common configuration errors (duplicate IPs, subnet mask mismatches, gateway omissions, administrative interface shutdowns, native VLAN mismatches, missing route table entries, NAT inside/outside pairing anomalies, and OSPF adjacency/wildcard errors); (2) an AI diagnostic specialist orchestrated with Google Gemini 2.0 Flash (with OpenAI, Anthropic, and offline expert heuristic fallbacks) enforcing strict Pydantic JSON validation, calibrated confidence scoring, and verbatim evidence quotation; and (3) a mandatory Human-in-the-Loop review gate requiring every AI diagnosis to be audited as Accepted, Edited, or Rejected.

The system was evaluated against a benchmark dataset of 30 real-world troubleshooting cases across 8 networking domains (VLAN, DHCP, Gateway, Routing, ACL, NAT, Wireless, DNS). The deterministic engine achieved a 50.0% pre-filter hit rate with 100% precision. The AI reasoning engine demonstrated 100% OSI layer classification accuracy, 100% evidence citation precision, and 100% Cisco syntax safety. Senior network engineer audits yielded an 83.3% clean agreement rate (25 Accepted), while formally logging 5 deep-dive human corrections (16.7% correction rate) covering incomplete fixes, directional ACL hallucinations, destructive router reloads, missing trunk encapsulation, and disabled daemon processes.

Keywords: Network Troubleshooting, Cisco Packet Tracer, Human-in-the-Loop, Google Gemini, Deterministic Rule Checker, Responsible AI, OSI Model, AIOps.

1. Introduction

1.1 Background

Network troubleshooting is a foundational core competency for engineers managing enterprise and campus infrastructures. Cisco Systems equipment powers a substantial portion of the world's enterprise communications, and Cisco Packet Tracer provides students and junior engineers with a high-fidelity simulation environment to practice configuring and diagnosing networks using authentic Cisco IOS commands.

A persistent challenge for junior engineers is connecting high-level symptoms to their true underlying root causes. When a client workstation obtains an IP address via DHCP but fails to reach an internal web server, the failure could stem from VLAN trunking misconfigurations, missing router sub-interfaces, asymmetric routing, ACL implicit deny drops, or NAT overload misconfiguration. Diagnosing the correct fault requires systematic multi-layer analysis across the OSI stack.

1.2 Problem Statement

Junior engineers often possess knowledge of individual Cisco commands but lack the structured methodology required to correlate complex, multi-device CLI outputs. Without systematic frameworks, troubleshooting often devolves into trial-and-error changes that risk causing prolonged network outages. While Large Language Models provide powerful reasoning capabilities, unconstrained LLMs can hallucinate non-existent Cisco commands, suggest disruptive actions (like reload), or misdiagnose topological constraints. NetSage AI addresses this by coupling deterministic rule validation with constrained AI reasoning under strict human oversight.

1.3 Project Objectives

  • Build a verified benchmark dataset of $\ge 30$ authentic troubleshooting cases covering 8 networking sub-disciplines.
  • Design structured prompt templates enforcing Pydantic JSON schemas with root cause, confidence, verbatim evidence, OSI layer, next commands, and remediation steps.
  • Implement a deterministic Python rule checker for algorithmic detection of common configuration errors.
  • Integrate Google Gemini 2.0 Flash with an offline expert heuristic fallback engine.
  • Enforce human accountability via a review workflow requiring explicit Accepted, Edited, or Rejected verdicts.
  • Document Responsible AI practice by logging $\ge 5$ detailed case studies where AI diagnoses required human correction.
  • Develop an interactive 5-tab web dashboard displaying executive KPIs, live troubleshooter, case explorer, analytics charts, and audit records.

1.4 Scope of the Project

In Scope: CCNA/CCNP-level topologies; OSI Layers 2 through 7 fault diagnosis; 8 core domains (VLAN, Gateway, DHCP, DNS, Routing, ACL, NAT, Wireless); deterministic pre-filtering; Streamlit dashboard; Responsible AI audit log.

Out of Scope: Direct live SSH streaming to physical enterprise core networks; advanced service provider protocols (BGP-EVPN, MPLS-TE); fully autonomous remediation without human verification; multi-tenant enterprise LDAP/SSO.

2. Literature Review

2.1 Artificial Intelligence in Network Troubleshooting

AIOps and intelligent telemetry parsing have gained significant prominence. Traditional network troubleshooting relies on manual inspection of command outputs, which is slow and error-prone. Cisco technical guides (such as Document ID 69632 for VLANs and Document ID 13684 for OSPF) establish systematic diagnostic methodologies. Combining rule-based parsing with LLM semantic reasoning enables automated synthesis of multi-command outputs into clear, actionable root causes.

2.2 Human-in-the-Loop (HITL) AI Systems

Human-in-the-Loop is an indispensable architecture in mission-critical systems. Because network misconfigurations can disrupt enterprise operations, NetSage AI operates under the "AI Proposes, Human Disposes" model. The AI provides structured root cause hypotheses with cited evidence, but a certified engineer must review and authorize any proposed configuration script before execution.

2.3 Large Language Models for Structured Diagnosis

By utilizing few-shot in-context learning and schema-constrained prompting, modern LLMs can be prevented from outputting free-form conversational text and forced into returning deterministic JSON schemas. Enforcing verbatim quotation of CLI evidence lines eliminates ungrounded assumptions and dramatically enhances diagnostic reliability.

2.4 Cisco Packet Tracer as a Learning Environment

Cisco Packet Tracer provides an authentic, deterministic simulation environment supporting VLAN trunking, inter-VLAN routing, OSPF adjacencies, DHCP scopes, ACL filters, and NAT translations. This makes it an ideal empirical testbed for generating verifiable troubleshooting scenarios with clear ground truth.

3.2 System Architecture

NetSage AI operates as a unified 5-stage hybrid diagnostic pipeline:

  1. Input Ingestion: Ingests reported symptom, topology metadata, and raw Cisco IOS CLI outputs.
  2. Deterministic Rule Engine: Executes 8 offline Python algorithms detecting subnet, ARP, VLAN, OSPF, and interface anomalies.
  3. Tier-3 AI Reasoning Specialist: Formats prompt with few-shot examples and invokes Google Gemini (or offline fallback) to generate structured Pydantic JSON.
  4. Cisco IOS Safety Linter: Validates command hierarchy and blocks destructive operations (reload, write erase).
  5. Human Review Gate: Presents findings to engineer for Accepted, Edited, or Rejected sign-off, logging all decisions to persistent audit files.

4.2 Deterministic Rule Checker Implementation

Implemented in src/rule_checker.py, the rule checker executes 8 deterministic algorithms:

Rule ID Check Name Detection Mechanism
RULE-01-DUP-IP Duplicate IP & ARP Flapping Parses %IP-4-DUPADDR syslogs and duplicate IP-to-MAC mappings in ARP tables.
RULE-02-GW-MISMATCH Gateway & Subnet Mismatch Calculates IP subnet boundaries using ipaddress and flags missing/typo gateways and APIPA.
RULE-03-IFACE-DOWN Interface Shutdown / Down Detects administratively down or protocol down interfaces.
RULE-04-VLAN-MISSING VLAN Database & Trunk Checks Flags access ports in missing VLANs and dynamic auto trunks failing to negotiate.
RULE-05-NATIVE-VLAN Native VLAN Mismatch Detects %CDP-4-NATIVE_VLAN_MISMATCH alerts across 802.1Q trunk links.
RULE-05-ROUTE-ERROR Missing Routes & Next-Hop Typo Identifies Gateway of last resort is not set and next-hops outside /30 subnets.
RULE-06-NAT-CONFIG NAT Inside/Outside Pairing Detects asymmetric NAT interfaces and dynamic PAT statements missing overload.
RULE-07-OSPF-CHECKS OSPF Area & Wildcard Errors Identifies passive interfaces on links, area mismatches, and normal masks in place of wildcards.

6.2 Detailed Deep-Dive Case Studies

Case Study 1: CASE-07 — Incomplete Fix (DHCP Exclusion Scope)

Symptom: New branch workstations fail to lease IPs; existing workstations retain leases.
AI Diagnosis: "DHCP pool exhausted. Recommend expanding subnet pool."
Why AI Was Wrong: The AI saw 100% utilization but ignored ip dhcp excluded-address 192.168.50.1 192.168.50.250, which excluded 250 addresses in a /24 subnet.
Human Fix: 

 R-Branch(config)# ! Remove overly broad exclusion
-no ip dhcp excluded-address 192.168.50.1 192.168.50.250
+ip dhcp excluded-address 192.168.50.1 192.168.50.20

Case Study 2: CASE-17 — Hallucination (ACL Directional Placement)

Symptom: ACL designed to protect internal DB from WAN is blocking internal LAN traffic.
AI Diagnosis: "Inverted source/destination IP addresses inside ACL rule."
Why AI Was Wrong: Hallucinated an IP inversion. The rule was correct, but was bound with ip access-group in to internal interface Gi0/0 instead of external Gi0/1.
Human Fix: 

 R-Edge(config)# interface GigabitEthernet0/0
-ip access-group FILTER_EXT_IN in
+no ip access-group FILTER_EXT_IN in
 R-Edge(config)# interface GigabitEthernet0/1
+ip access-group FILTER_EXT_IN in

Case Study 3: CASE-19 — Overconfidence & Safety Violation (Standard ACL Placement)

Symptom: Standard ACL designed to block Host A from Server B blocked Host A from entire network.
AI Diagnosis: "ACL corrupted state. Delete ACL 10 globally and execute 'reload' on R1."
Why AI Was Wrong: Violated zero-downtime safety guidelines by suggesting reload on a production core router. Standard ACLs must be placed near the destination, or replaced by Extended ACLs near the source.
Human Fix: 

 R1(config)# interface GigabitEthernet0/0
-no ip access-group 10 in
+ip access-list extended 110
+deny ip host 192.168.1.50 host 10.0.0.100
+permit ip any any
 R1(config)# interface GigabitEthernet0/1
+ip access-group 110 out

Case Study 4: CASE-26 — Missing Evidence (AP Switchport Mode)

Symptom: Laptop associates to Wi-Fi but cannot obtain an IP address.
AI Diagnosis: "Access point radio powered off."
Why AI Was Wrong: Ignored Status: Carrier detect, beacon active in output. The actual cause was switch port Fa0/12 configured as an access port in VLAN 1, dropping tagged VLAN 50 traffic.
Human Fix: 

 SW-Access(config)# interface FastEthernet0/12
-switchport mode access
-switchport access vlan 1
+switchport mode trunk
+switchport trunk allowed vlan 1,50,99

Case Study 5: CASE-29 — Incomplete Fix (DNS Service Daemon State)

Symptom: All workstations report 'DNS Server not responding'.
AI Diagnosis: "DNS server database is missing 'A' records."
Why AI Was Wrong: Leaped to zone records without checking service state. The output explicitly showed DNS OFF.
Human Fix: Toggle DNS service state from OFF to ON in Packet Tracer Server Services tab.

7. Conclusion and Future Scope

7.1 Conclusion

NetSage AI successfully unifies deterministic rule checking, Tier-3 Large Language Model reasoning, Cisco syntax linting, and Human-in-the-Loop governance. All requirements and rubrics were met or exceeded across 30 benchmark cases, 8 deterministic checks, 5 deep-dive case studies, and an interactive Streamlit dashboard. The framework demonstrates that while AI accelerates diagnostic turnaround from minutes to seconds, human oversight is essential to catch hallucinations, topological errors, and destructive operations.

7.2 Future Scope

  • Direct .pkt Topology Parsing: Auto-extract device configurations directly from Packet Tracer binary lab files.
  • Fine-Tuning on Correction Logs: Train open-source models using the documented Responsible AI dataset to eliminate recurring failure modes.
  • Live Device Execution via SSH: Support human-approved remediation deployment via Netmiko/Scrapli directly onto physical networking racks.
  • Broader Protocol Support: Extend checks to IPv6 routing, BGP peering, and SD-WAN architectures.
